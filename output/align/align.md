# 能力管理平台 - 需求对齐稿

## 一、需求概述

在桂教通平台上建设能力管理模块，支持开发者入驻 → 能力上架 → 应用授权 → 接口申请审批 → 调用的全链路，服务三类角色（机构管理员、桂教通超管、开发者管理员），一期交付开发者管理、接口管理、接口申请审批、接口调用记录、客户端授权关联、运营统计、应用管理、开发者账号与接口中心、数据同步申请与审批；双向同步执行/签字授权/AppKey 分配与租户管理一期不建（复用桂教通体系）。

## 二、建设范围

### （一）一期范围

完整覆盖 `input/能力管理平台.xlsx` 中 72 个功能点，按业务模块划分：

| 模块 | 核心功能 | 涉及角色 |
|------|---------|---------|
| 开发者管理 | 开发者信息 CRUD、邀请注册、确认合作、取消/重新合作、启用/停用 | 机构管理员、桂教通超管 |
| API 接口管理 | 接口 CRUD、接口文档、应用授权、授权/取消授权、接口停用/启用 | 机构管理员、桂教通超管 |
| 接口申请与审批 | 接口申请记录、申请审核/查看 | 机构管理员、桂教通超管、开发者管理员 |
| 运营统计 | 接口统计（总数/分布/申请量/授权量）、开发者统计（总数/合作状态）、应用统计（授权数/授权接口数）、支持时间范围筛选和导出 | 机构管理员、桂教通超管 |
| 客户端授权关联 | 客户端授权 CRUD、启用/停用 | 桂教通超管 |

| 开发者接口中心 | 接口列表、文档、申请、申请记录 | 开发者管理员 |
| 应用管理 | 应用查看/新增、应用授权关联（应用ID、suiteKey 由桂教通体系提供） | 开发者管理员 |

## 三、建设方式

**类型：iteration（在桂教通平台上扩展）**

判断依据：
- 桂教通已上线运行，能力管理是其"超管后台"下的一个新模块（原超管后台已有能力管理菜单）；
- 用户体系、机构树、消息通知、审计日志、应用实体、密钥体系等基础能力均复用桂教通现有能力，不重复建设；
- 前端在桂教通现有框架内增加菜单和页面，后端在能力管理域增加业务模块。

挂载点：
- 桂教通超管 → 超管后台 → 能力管理（已存在菜单入口）
- 机构管理员 → 组织中心 → 能力管理（已有入口）
- 开发者管理员 → 开发者后台 → 接口中心（已有开发者后台框架）

## 七、数据同步详细说明

### 7.1 业务背景

数据同步是能力管理平台的配套数据交换通道。开发者完成合作后，可能需要获取桂教通平台上的基础数据（如机构、部门、人员），也需将其业务系统的数据回流到桂教通。

### 7.2 双向数据流

#### 流向一：桂教通平台 → 开发者业务系统（平台推数据）

- **触发方**：开发者管理员（开发者方）
- **场景**：开发者需要桂教通的机构部门人员等基础数据用于自身业务
- **流程**：
  1. 开发者开发者管理员提交数据同步申请，填写：
     - 同步方向（平台→开发者）
     - 申请数据范围（如：指定机构/部门/人员，或全部）
     - 同步目标（开发者指定的数据表名）
     - 申请理由
  2. 桂教通超管审批，可驳回（驳回后开发者可重新编辑提交）
  3. 审批通过后，超管进行**签字授权**（确认数据出平台的法律责任）
  4. 签字授权后，系统自动执行数据推送任务，将桂教通数据写入开发者指定的数据表
  5. 开发者通过分配的 AppKey/SecretKey 访问目标表中的数据

#### 流向二：开发者业务系统 → 桂教通平台（业务系统推数据）

- **触发方**：开发者管理员（开发者方）
- **场景**：开发者业务系统的数据需要同步到桂教通（如"上述放过来的数据流向"——即与流向一方向相反的回流）
- **流程**：
  1. 开发者开发者管理员提交数据同步申请，填写：
     - 同步方向（开发者→平台）
     - 同步数据描述（什么数据、格式、周期）
     - 申请理由
  2. 桂教通超管审批，可驳回
  3. 审批通过后，超管进行签字授权
  4. 签字授权后，分配 AppKey 和 SecretKey，开发者按约定接口将数据推送到桂教通指定数据表

### 7.3 签字授权说明

- **签字人**：桂教通超管（数据出/入平台的管理责任人）
- **签字时机**：审批通过后、实际执行同步前
- **签字内容**：确认数据范围、同步方向、目标表、数据安全责任
- **签字后流程**：签字后才真正执行同步或发放密钥，签字不可跳过

### 7.4 同步任务执行

- 签字授权后系统自动创建同步任务
- 任务状态：待执行 / 执行中 / 成功 / 失败 / 已取消
- 支持查看同步日志（同步了哪些数据、条数、时间）
- 失败时支持手动重试

### 7.5 密钥体系

- 数据同步通道分配独立的 AppKey + SecretKey，与 API 接口鉴权的密钥分开
- 密钥由桂教通超管在审批签字后分配
- 支持密钥重置

## 需求变更记录

> 以下为相对初版原型/PRD/Design 的增量调整，已在 P05、P16、P22、P28Apply、P32、P33 及对应文档同步落地。

### 变更 1：桂教通超管 - 新增/编辑接口（P05）

- **新增「接口类型」字段**：单选（个人 / 机构），必填；与既有「数据敏感等级（敏感/非敏感）」区分，后者保留。
- **删除「调用身份」字段**：原调用主体概念移除，不再采集。
- **删除「接口签名类型」字段**。
- **「是否需要学校审批」改名为「是否机构审批」**：语义由学校审批调整为机构审批，radio 必选（是/否）。
- **全局 URL 唯一**：接口请求地址需全局唯一，保存时若已存在相同地址（排除自身）则禁止保存。

### 变更 2：开发者管理员 - 应用接口申请（P28Apply）

- **授权接口弹窗仅展示「是否需要授权=是」的接口**（原展示全部对外可见接口）。
